# Improvement Request

- [Accept TAN production as a deployment target](accept-tan-production-as-a-deployment-target.md) - Resolve or explicitly accept the production gates recorded in the clickhouse-migrate adoption evidence (startup crash disposition, security and patch review, unselected deployment target, Linux amd64 application image, uncertified managed endpoint) for Altinity 26.3.60.10002.altinitystable on tan-production, and release an image whose identity and evidence TAN's production stack can pin.
- [Add a percentile aggregation to custom metrics](add-a-percentile-aggregation-to-custom-metrics.md) - Let /metrics/custom and saved metric definitions compute a percentile (for example p50, p75 or p95) of a declared numeric property, so consumers can report latency-like values such as web vitals and page durations, where averages mislead.
- [Attribute conversions to first-touch acquisition](attribute-conversions-to-first-touch-acquisition.md) - Add converted-user and conversion-rate measures to /metrics/acquisition for a caller-supplied list of conversion events, credited to the visitor's first-touch channel, referrer, campaign or landing page, so a consumer can rank traffic sources by how well they convert.
- [Classify AI assistant referrals as their own channel](classify-ai-assistant-referrals-as-a-channel.md) - Add channel rule version 2 with an ai_assistant channel for visits referred by ChatGPT, Perplexity, Claude, Gemini, Copilot and similar assistants, which version 1 splits across organic_search, referral and other.
- [Count sessions that contain an event](count-sessions-that-contain-an-event.md) - Let /metrics/sessions select the web sessions that contain at least one event of a given name (for example client_error), with the route's existing grouping, grains and attribute filters, so a consumer can report the share of sessions that saw an error.
- [Count unique users over a whole query range](count-unique-users-over-a-whole-range.md) - Let the users, custom unique_count and acquisition users measures return one unbucketed answer per group for the whole from..to range, so a consumer can show exact visitors for a period instead of summing daily buckets that count returning users more than once.
- [Declare client error and web vital events](declare-client-error-and-web-vital-events.md) - Declare client_error and web_vital event schemas in the registry, and ask the browser SDK to capture them, so a consumer can report JavaScript errors and Core Web Vitals by page next to product analytics.
- [Filter and group events by the attributes of their session](filter-and-group-events-by-their-session-attributes.md) - Add session-scoped dimensions (for example session:channel, session:referrer_host, session:utm_campaign, session:entry_page) that page-views, users and custom metrics can filter and group by, selecting each event by the first-touch attributes of the web session it belongs to, so a consumer can report the pages viewed and the people seen during visits from one source.
- [Keep Kansoku starting and accepting events while ClickHouse is unavailable](keep-kansoku-starting-and-accepting-events-while-clickhouse-is-unavailable.md) - Make the PostgreSQL queue the buffer between Kansoku and ClickHouse in every case, so kansoku-server always starts and keeps receiving events during a ClickHouse or replica outage, where today replicated startup exits if any replica is unreachable and readiness removes the server from traffic.
- [Keep writes, reads and maintenance jobs correct on a replicated cluster](keep-writes-and-maintenance-jobs-correct-on-a-replicated-cluster.md) - Make the writer's durability, read-after-write behaviour and the erase/retention maintenance jobs' quiesce and mutation checks hold across every replica of a replicated ClickHouse cluster reached through one load-balanced endpoint, where today each check sees only the replica its connection landed on.
- [Name the experiment conversion rate measure correctly in the query guide](name-the-experiment-conversion-rate-measure-in-the-query-guide.md) - The query guide says the experiment conversion endpoint returns a measure named rate, while the query compiler and its tests emit conversion_rate; correct the guide so API consumers read the measure kansoku actually returns.
- [Operate Kansoku's ClickHouse schema and maintenance on a shared server](operate-the-clickhouse-schema-on-a-shared-server.md) - Let Kansoku's ClickHouse maintenance ceremony, admin jobs and restore verification work on a ClickHouse server shared with other apps, using tenant-scoped quiesce evidence and on-demand app-database backups instead of server restarts, without reading other users' queries.
- [Read identified users, their profiles and their event history](read-identified-users-their-profiles-and-event-history.md) - Add an account-scoped, read-only users resource that lists identified users with their current traits and first and last activity, reads one user's profile and identity evidence summary, pages through one user's resolved events newest first, and counts identified and anonymous subjects active in a range, so a consumer can show a user directory and a per-user drill-down.
- [Run ClickHouse migrations on a replicated cluster](run-clickhouse-migrations-on-a-replicated-cluster.md) - Let kansoku-ch-migrate select clickhouse-migrate's replicated target from its environment and run a separate replicated baseline with Replicated*MergeTree engines and a fresh v2 ledger, leaving the direct target and its bound history unchanged, so Kansoku can initialise and upgrade its schema on TAN's two-replica production ClickHouse cluster.
- [Create the ingest queue in migrations so the server runs with a DML-only PostgreSQL role](run-the-server-with-a-dml-only-postgresql-role.md) - Move PGMQ queue creation from kansoku-server startup into kansoku-migrate, make startup only verify the queue, and document which role each binary uses, so Kansoku runs on a managed PostgreSQL app database whose runtime role has no DDL rights.
- [Save named analyses for an account](save-named-analyses-for-an-account.md) - Add an account-scoped saved-analysis resource holding a name, a description, a kind (trends, funnel or retention) and a bounded client-versioned JSON document, with create, read, update and delete, cursor pages ordered by most recent update, a kind filter and optimistic concurrency, so consumers can keep a shared library of analyses that people reopen.
- [Select one identified user in metric queries](select-one-identified-user-in-metric-queries.md) - Add a filter dimension that selects the events, sessions and activity of one or a few identified users by user ID after identity resolution, on the event, page-view, users, sessions, acquisition, revenue, feature-adoption and custom metric routes, so a consumer can chart one user's activity with the aggregate routes it already uses.
- [Stop counting client errors and web vitals as session engagement](stop-counting-client-errors-and-web-vitals-as-session-engagement.md) - Classify client_error and web_vital as non-engagement events in the session rules, as session_start and page_leave already are, so that turning on kansoku-js's opt-in error and vital capture does not remove bounces and change a site's bounce rate.
- [Stream recent events and page views over WebSockets](stream-recent-events-and-page-views-over-websockets.md) - Provide an authenticated account-scoped WebSocket subscription with a bounded recent snapshot and live updates so consumers can display current events and page views without polling.
